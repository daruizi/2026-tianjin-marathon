## 训练进展 · W4–W13 阶段复盘 (2026-06-15 ~ 08-24)

**数据源**: `Activities/6月15日-8月24日/` 共 **81 个 Garmin FIT 文件**(63 场跑步 + 15 次通勤骑行 + 3 条非跑步记录),
由 `fitparse` 逐条解析 record / lap / session 消息,**42.5 万条秒级心率采样**。
所有配速块、脱钩率、心率区间时长均由秒级数据重算,未采用 Garmin 汇总字段。

### 阶段评级: **B+** — 引擎造好了,但从没装到赛道上

| 指标 | 结果 | 对照 |
|---|---|---|
| 总跑量 | **1361.9 km** / 118.0 h | 计划 1180 km · **+15%** |
| 训练出勤 | **60 / 60 天** 零缺勤 | 69 天里休息 9 天(全部周一) |
| 165+ bpm 周停留 | **2 → 71 min** | W4 → W13 · **35 倍** |
| 周三主课 | **9.7 km @4:06 → 15.9 km @3:57** | 峰值心率 174 → **183** |
| 长跑最长连续 MP 段 | **3.1 km** | 计划要求 18 km · 达成 **17%** |
| 平均气温 | 26.0℃(峰值 35℃) | 全程夏训,无一次因天气缩水 |

### ✅ 做对了什么

1. **执行力接近满分** — 60 个训练日一次没缺,周量方差极小(134.6–139.2 km)。
2. **五年没突破的「高心率耐受」被真正打开** — 这正是赛前诊断出的核心缺口。
   165+ bpm 停留从 2 min/周 涨到 71 min/周,175+ 从零到 11 min/周,实测最大心率摸到 **183**。
3. **周三质量课量价齐升** — W11 的 9×1000m @3:52、W13 的 3×(4×1000m) 递进 @4:12/4:04/3:58 + 10×390m @3:31,
   都是过去两年没有过的课。
4. **跑姿经济性改善** — 高速段垂直振幅比 7.11 → **5.92**,触地 247 → **238 ms**,步幅 1160 → **1327 mm**。

### ⚠️ 三个必须修正的偏差

1. **【决定成败】长跑内嵌 MP 段,十周 0 次执行。**
   计划要求 8 → 6 → 10 → 12 → 15 → 18 → 18 km @ 4:08;实际 11 次长跑全是同一模板:
   36.7 km 匀速有氧,前 20 km 跑 5:10–5:45,末段自然滑到 4:25–4:50。
   长跑内部能连续维持 4:08 的最长距离只有 **3.1 km**,维持 4:20 的最长只有 5.2 km。
2. **十周没有一次减量周。** W4 / W9 / W10 计划 100 / 105 / 100 km,实际全部 135–136 km(**+31 ~ +36 km**)。
   七月单月 600.3 km(月目标 500)。后果:长跑脱钩从 −3.6% 恶化到 **−32.6%**,Garmin TE 5.0(过量)占全部场次的 **29%**。
3. **W9 的 ★ 半马 go/no-go 测试被跳过**,导致目前没有任何干净的体能基准;
   同时 W12 / W13 出现周末双长跑(64 km / 60 km 两天),**周六吃掉了周日**。

> 次要项:力量训练十周无有效记录(计划 20 次)。若已做请开始记录,否则在 136 km/周 的负荷下这是跟腱/小腿的实际风险敞口。

### 📊 结论

- **按现状直接上场**: 大概率 **2:57–2:59**(仍可能是新 PB,靠夏训的有氧厚度)。
- **执行 v2 修订方案且 W16 / W18 两堂关键课达标**: **2:54–2:56** 完全在射程内。
- 差距不在引擎,在**「用 4:08 跑很久」**这一件事。剩余 9 周只做这一件事。

原计划 W15 直接要 22 km MP、W16 要 25 km MP —— 在「历史最长 3.1 km」的基础上不可能落地。重建的阶梯:

3. **长跑从「36.7 km 匀速」改成「30–35 km 带 MP」** — 不再追求距离数字。时长反而更短(2h40–2h55),专项价值高一个量级。

### ⚠️ 气温 → MP 等效配速(2026-09-06 据 W15 实测更新)

**降温到了。** 工作日气温从 W14 的 21–28℃ 降到 W15 的 **19–21℃**,周均 23.3 → **20.8℃**。
这意味着**工作日的课可以重新「看配速」了**,不必再只看心率。

**但周日长跑仍是例外**:9/6 起跑 05:12,跑到后段太阳升起,气温从 23℃ 一路涨到 28℃,全程中位 **25℃**。
长跑判读继续用「23–25℃ → 4:17–4:22」这一档 —— 这也是为什么 9/6 的 9.41 km @4:21.8 是**达标**而非勉强,
它正好压在等效区间的下沿。

| 气温 | MP 4:08 的等效配速 | 判据 |
|---|---|---|
| 10–14℃(比赛日预期) | **4:08** | 看配速 |
| **18–20℃(当前 · 工作日)** | **4:12–4:15** | **看配速** |
| **23–25℃(当前 · 周日长跑后段)** | **4:17–4:22** | **配速 + 心率,取先到者** |
| 26–28℃ | 4:21–4:28 | 只看心率 155–163 |
| 30℃+ | 4:27–4:36 | 只看心率,或把专项课挪早 |

> **对策**:把周日起跑提前到 **05:00 以前**。W16 的 16 km 连续 MP 需要约 70 分钟,
> 早 15 分钟出门就能把整个专项段留在 23℃ 以内。

**比赛日期 2026-10-25 为推测值**(基于 2024-10-19 与 2025-10-25 规律)。官方公告出来后,请修改 `data.js`:

```javascript
const RACE_DAY = new Date('2026-10-25T07:30:00+08:00');  // 改为官方日期
```

## 功能特性

### 交互
- **本周聚焦**: 自动识别当前是第几周,顶部高亮当周 6 天清单
- **完成勾选**: 每天点击标记完成,数据存于浏览器 localStorage,刷新不丢
- **整周勾选**: 表格中点击 ○ 标记整周完成
- **详情弹窗**: 点击任意周看每日详细训练
- **进度统计**: 顶部显示距比赛天数 / 当前周次 / 完成天数 / 训练周期进度

### 工具
- **配速计算器**: 输入目标全马时间,自动算 E/M/T/I/R 各强度区间配速
- **训练日志**: 记录每周主课 (周三质量课 + 周日长跑) 的 RPE / 感受 / 实际完成 / 心得复盘, 时间线展示
- **数据图表** (Chart.js):
  - 4 场全马成绩 + 均HR 对比
  - 5km 分段配速曲线
  - 22 周训练量分布
- **导出进度**: 一键导出 JSON (含完成记录 + 日志),可备份/迁移到其他设备
- **重置进度**: 重新开始训练时清空记录 (可选清空日志)

### 显示
- **暗色/浅色主题**: 顶部按钮切换,记忆偏好
- **响应式**: 适配手机 / 平板 / 桌面
- **打印优化**: 顶部"⎙ 打印"按钮,自动隐藏交互元素,适合 A4 打印

2. 上传所有文件到仓库根目录:

## 跨设备同步配置

应用使用 **GitHub Gist API** 实现多设备数据同步。所有数据 (进度勾选 + 训练日志) 存在你私人 Gist 中,
两台或多台电脑用同一个 Personal Access Token (PAT) 即可双向同步。

### 第一台设备:开启同步

1. **创建 PAT**: 访问 https://github.com/settings/tokens?type=beta
   - Token type: **Fine-grained personal access token**
   - Token name: 任意 (例如 "TJM 2026")
   - Expiration: 自选 (建议 1 年)
   - Repository access: **Public Repositories (read-only)** (无需 repo 权限)
   - **Permissions → Account permissions → Gists → 选 Read and write**
   - 生成并复制 PAT (以 `github_pat_` 开头)
2. 在网站点击右上 **☁ 同步** → 粘贴 PAT → 点 **开启同步**
3. 应用自动创建一个名为 `2026 TJM Training Progress (DO NOT DELETE)` 的私有 Gist
4. 此后每次勾选 / 写日志后, 数据 2 秒后自动推送到 Gist

### 第二台设备:接入同步

1. 在第二台电脑上打开同一个 GitHub Pages URL
2. 点击右上 **☁ 同步** → 粘贴**相同的 PAT** (不需要重新创建)
3. 应用自动识别已有 Gist 并拉取数据合并到本地
4. 双向同步从此开始 — 任一设备的修改 2 秒内同步到另一台

### 同步机制

- **触发**: 任意保存 (勾选 / 日志保存) 后防抖 2 秒推送
- **启动**: 打开网页时自动拉一次远程, 合并本地
- **合并策略**:
  - **完成勾选 (progress)**: 任一端为 true 即 true (避免误删)
  - **训练日志 (logs)**: 按 `savedAt` 时间戳取较新者
- **手动同步**: 任何时候点 ☁ 同步 → 立即同步
- **状态指示**: 按钮颜色 — 绿✓=正常 / 橙↻=同步中 / 红⚠=错误

### 安全说明

- **PAT 仅存浏览器 localStorage**, 不发送任何第三方
- **Gist 设置为 Secret** (Unlisted), 只有持 Gist URL 才能访问
- 所有 API 调用直接到 `api.github.com`, 没有中间服务器
- 推荐 fine-grained token, 限定 Gists 权限, 避免使用 classic token

### 取消同步

点 ☁ 同步 → 取消同步。本地 PAT 和 Gist ID 关联被清除, Gist 本身不删 (可手动到 https://gist.github.com 删除)。

## 训练计划方法论来源

- Jack Daniels 《Daniels' Running Formula》 — VDOT 系统 / 5 训练区间
- Pfitzinger & Douglas 《Advanced Marathoning》 — MP 长跑特异性(v2 修订的核心依据)
- Rønnestad & Mujika 2014 — 耐力跑者大重量力量训练
- 4 场用户全马 FIT 文件秒级数据分析
- **v2 修订依据**: W4–W13 共 81 个训练 FIT 文件秒级解析(42.5 万条心率采样),
  重算连续配速块 / 心率区间时长 / 长跑脱钩率 / 跑姿指标 —— 见 [W4–W13 十周阶段复盘](W4-W13-十周阶段复盘.html)

### 分析方法说明

- **「连续 MP 段」**: 100 m 重采样后,**平均配速**能维持在阈值(4:08)以内的最长连续距离。
  用平均配速而非逐点配速,避免红绿灯 / GPS 噪点误断连续块。
- **「脱钩率」**: 后半程(速度÷心率) ÷ 前半程(速度÷心率) − 1。健康区间 0 ~ −5%。
- **「心率区间」**: 按实测最大心率 183(2026-08-05)划分,非年龄公式推算。
- **「主课有效距离」**: 质量课中排除热身、缓和、慢跑间歇后的净距离,由 lap 消息识别(配速 ≤4:40 的手动分段)。
- **气温折算表**为含湿度影响的经验区间,仅供判读参考,不是精确换算。
